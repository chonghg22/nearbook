# P1-07 검색 응답 시간·페이지 정합성

## 문제와 범위

P1-06 운영 검증에서 제목 첫 요청 18,284ms, 출판사 10,659ms가 관측됐다. 웹 요청 제한은 15,000ms다. 기존 서비스는 로컬 결과가 있어도 검색 통계 DB와 정보나루 보충을 기다렸으며, 다른 검색 기준으로 계산된 외부 총건수를 페이지 수에 섞었다.

이번 변경은 검색 API·공용 타입·웹 검색 화면만 다룬다. DB 스키마·강제 갱신·색인 포맷·지도 설정·PWA·P1-08은 변경하지 않는다. 평상시 검색에서 실행하던 공급자 메타데이터 캐시는 유지한다.

## 응답과 보충

- HTTP 검색은 Orama의 단일 조회가 반환한 `hits`와 `total`을 그대로 사용한다. 정보나루 통계 조회·외부 보충·추천 SQL을 기다리지 않는다.
- 외부 총건수는 검색 API의 `total`에 사용하지 않는다. 총건수는 현재 색인에서 검색 가능한 도서이며 외부 카탈로그 전체 수가 아니다.
- 정보나루·알라딘은 백그라운드에서 실행한다. 정규화된 검색어와 실제 검색 유형이 같은 요청은 페이지·정렬·페이지 크기에 관계없이 합쳐진다.
- 한 번에 정보나루 첫 페이지 최대 60권과 알라딘 최대 10권만 보충한다. 공급자 60/40권 페이지와 로컬 10권 페이지는 대응하지 않으므로 로컬 페이지 번호로 추가 다운로드하지 않는다. 외부 전체 결과 수집 기능을 제공하는 변경이 아니다.
- ISBN 누락은 정확 ISBN 메타데이터만 조회하며 다른 ISBN은 받아들이지 않는다. 기존 체크 숫자 검증·10→13 정규화·검색 순위는 유지한다.
- 서로 다른 검색어의 동시 보충은 최대 16개 작업이다. 작업당 공급자는 최대 두 곳이며 기존 공급자 요청 제한·timeout이 적용된다. 모든 작업이 DB에서 멈추면 슬롯은 유지되고 신규 보충은 대기 상태가 되지만 로컬 결과 반환은 막지 않는다. 강제 취소나 DB timeout 변경은 이번 범위 밖이다.
- 성공 보충은 한 시간, 정보나루/색인 보충 실패는 30초간 재요청을 억제한다. 실패는 정상 0건으로 처리하지 않는다. 알라딘만 실패한 경우 정보나루의 정상 결과를 무효화하지 않는다.

## 상태·UI

공용 응답에 선택적 boolean `enrichmentPending`, `enrichmentFailed`를 추가한다. 기존 응답에는 필드가 없어도 파싱된다.

- 로컬 책이 있으면 즉시 표시하고 백그라운드 보충을 기다리지 않는다.
- 로컬 총건수가 0이고 보충 중/슬롯 부족이면 확인 중 안내·스켈레톤을 표시한다. 0건 확정이나 정상 빈 화면을 표시하지 않는다.
- 웹은 확인 중 응답에 한해 2초 간격으로 최대 15회 재확인한다. 실제 HTTP 시간은 별도이므로 총 벽시계 30초를 보장하는 의미는 아니다. 종료 후 수동 다시 시도를 제공하며 화면 변경/언마운트 시 타이머를 정리한다.
- 실패 상태는 오류/다시 시도로 구분한다. 성공적으로 확인된 빈 결과만 정상 빈 화면으로 표시한다. 이는 현재 색인·제한된 보충 결과의 부재이지 책이 세상에 존재하지 않는다는 보장이 아니다.
- 로딩 중 총건수를 0으로 확정하지 않는다. 범위를 벗어난 기존 URL은 책 부재 대신 첫 페이지 복귀를 제공한다.

## 캐시

- 기존 의존성 `lru-cache`를 사용한다. 응답 캐시 최대 500개/60초, 보충 결과 상태 최대 500개/성공 1시간·실패 30초이며 검색 접근 시 만료 항목을 정리한다. 최대 크기를 넘겨 제거된 보충 상태는 다음 검색에 재보충될 수 있다.
- 색인에 revision을 추가한다. 단일/다중 upsert 및 전체 rebuild가 revision을 변경하므로 다른 모듈에서 색인을 변경해도 기존 응답 캐시를 재사용하지 않는다.
- 조회 도중 revision이 달라진 응답은 캐시하지 않는다. 보충 종료 시 응답 캐시를 비운다. 확인 중·실패 응답도 캐시하지 않는다.
- 프로세스 내 캐시/동시 작업 관리이며 다중 API 인스턴스 간 전역 중복 방지는 제공하지 않는다.

## 검증

실제 Orama의 순위·페이지 및 revision 테스트, 중단된 공급자 promise로 로컬 우선 반환, 동시 요청 병합·타입/ISBN 격리, 외부 총건수 배제, 실패 재시도·TTL·최대 크기·다른 검색어 색인 변경 무효화, cold 검색 확인 상태를 검증한다. DOM에서 초기 로딩/확인 중/정상 0건/오류를 구분하고 자동 재확인 제한·타이머 정리·첫 페이지 복귀·파서 호환성을 검증한다.

운영 배포는 최종 CI 및 프리뷰 검증 통과 후 승인 범위 안에서 진행한다. 운영 후 공개 검색·ISBN·페이지 정합성·응답 시간·API health와 웹 자산을 확인하며 실제 외부 timeout을 유발하거나 강제 갱신하지 않는다.
