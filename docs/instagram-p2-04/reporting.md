# 집계 절차

현재 운영 DB 저장 행/시간 기준을 확인하지 못했고 게시도 하지 않았으므로 수집 실적·전환율·재방문율은 미측정이다. 생성일이나 승인일을 게시일로 쓰지 않는다.

1. `readiness.sql`은 읽기 전용 거래에서 session TimeZone·컬럼 기본값·최근 v2 수집 시각을 확인하는 초안이다. TimeZone 하나만 보고 UTC 저장이라고 단정하지 않는다. 실제 배포의 쓰기 세션 기준과 함께 확인한다. 이 쿼리를 실행하거나 운영 데이터 검증을 마쳤다고 주장하지 않는다.
2. 데이터 저장이 검증되면 `docs/analytics-weekly.sql`의1번으로 schemaVersion2 수집을 확인한다. 프로필/스토리 source 두 값과 자체 QA source를 구분한다.
3. 2번의 `traffic_source`별 visit/search/book_view/checked/next_action 세션 수를 사용한다. 본 실험은 아래 두 행만 집계 대상으로 삼는다. 상태 노출 이벤트만으로 완료를 세지 않는다.
   - instagram-bio-p204-20261020
   - instagram-story-p204-20261020
4. 3/4/5번으로 요청 실패·unknown·정상0건·공식 사이트와 길찾기를 따로 확인한다. 요청 수는 세션 수와 다르다. 공유 프로필 링크로 들어온 웹 전환을 개별 피드/릴스 실적으로 중복 기입하지 않는다.
5. 기존6번은 전체 브라우저 최초 관측 코호트다. 이를 인스타 채널별7일 재방문이라고 표기하지 않는다. 게시 이후 캠페인 첫 유입 코호트·그 이후 모든 source의 다른 세션 방문을 연결하는 별도 집계가 필요하며, 운영 접근 확보 후 준비/검증한다. 계측 이전 방문을 실제 신규 사용자로 단정하지 않는다.
6. 기존 SQL은 최근7일 창이다. D7/D14 각 창의 중간 보고에 사용하고, 전체14일 누계와 성숙 코호트 비교는 실제 게시 시각·종료 시각을 고정한 별도 집계로 검증한다. 일별 서로 다른 세션 수를 더해14일 고유 세션이라고 하지 않는다.

게시물 결과는 계정에서 실제 제공하는 지표만 results.csv에 남긴다. 값이 없으면 빈칸/미측정, 0이 관측됐을 때만0이다. 운영 원시 이벤트·anonymousId·검색어·정확한 위치는 공개 PR·홍보글에 복사하지 않는다. 반복 피드백은 이름/계정 핸들 없이 익명 문제 유형으로 기록한다.

확인해야 할 남은 작업: 운영 저장 행/시각 검증 → 실제 게시·기간 시작 → 채널 코호트 집계 검증 →14일 관측/성숙한 재방문 확인 → 다음 개선 결정. 계정 접근 거절이나 수집 미확인 상태를 우회해 실험 완료 처리하지 않는다.
