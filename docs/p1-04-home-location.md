# P1-04 — 홈 검색과 기준 위치 선택

## 범위

운영 main `de38fc8`에서 별도 worktree/branch로 진행한다. 웹만 수정하며 API/DB/지도 권한/강제 갱신/P1-05는 포함하지 않는다. 기존 검색·ISBN 스캐너·LocationProvider·지역 좌표 목록을 재사용한다.

## 변경

- 소개 아래에 홈 검색 form, 데스크톱/모바일 공통 ISBN 바코드 스캔 링크, 로그인/GPS 없이 검색 가능 안내와 기준 위치 변경을 배치.
- 기본 서울은 “기준 지역: 서울특별시”로 표시. 수동 선택은 “기준 지역/기준 도서관”, GPS 성공은 “GPS 기준”, 저장된 GPS는 “저장된 GPS 기준”으로 구분한다. 지역은 중심 좌표이며 지역 전체 도서관 조회라고 오인시키지 않는다.
- 지역·도서관 변경은 홈 상단과 도서관 영역, 기존 책 상세에서 항상 접근 가능. GPS를 자동 요청하지 않고 사용자가 버튼을 누를 때만 요청한다. 기존 지역 목록의 범위를 임의 확장하지 않는다.
- Modal은 기존 Radix Dialog로 focus trap/Escape/닫기/호출 버튼 focus 복귀를 지원한다. GPS 거부·미지원·시간 초과·일반 실패를 구분하고 “GPS 없이 지역 직접 선택”을 제공한다.
- 저장 위치 JSON/모드/좌표/id를 검증한다. 지역의 좌표/라벨은 알려진 slug에서 재구성하며 저장소 차단 시에도 메모리에서 수동 선택 가능. 기존 저장 GPS는 현재 위치로 주장하지 않는다. 위치 저장 정책·GPS 권한 자체는 변경하지 않는다.
- GPS 종료/탭 변경/수동 선택/Provider 종료 후 늦은 응답이 새 기준을 덮어쓰지 않는다.
- 홈 목록은 선택 기준 좌표의 `/api/libraries/near?lat=…&lng=…&radius=5`만 사용한다. 지도 pan으로 기준을 바꾸거나 이전 지역·전국 인기 도서관을 섞지 않는다. 정상 빈 목록·실패·로딩을 구분하고 실패에는 수동 재시도 제공.
- 거리는 실제 `distanceKm`만 “기준점에서 …km”로 표시. 0도 유효하며 누락 시 임의 0.5km를 표시하지 않는다. 반경5km/최대12곳과 지도 이동 시 기준 고정 안내.

## 검증

- frozen lock install, lint/type-check/build 및 전체 테스트 검증. 웹 DOM 테스트에 dev-only `@testing-library/react@16.3.0`, `jsdom@26.1.0` 추가. 기존 Turbo 2.9.12 등 실행 의존성 버전 유지.
- 로컬 최종: Node237 + 웹 Vitest202 + API Jest58 = **497개** (기존447개 + P1-04 신규50개). 웹20파일 모두 성공, lint 경고/오류 없음, type-check/build 성공. API Jest58은 변경 없는 기존 suite 캐시 결과이며 PR CI에서는 새 runner로 재검증한다.
- location state/GPS/home parser 순수 테스트와 jsdom interaction 테스트: 비로그인 첫 방문 검색/스캔, 수동 지역 저장/복원, 도서관 검색/선택, GPS 성공/거부/미지원/시간 초과/취소, 늦은 응답, 잘못된 저장소/차단, Escape/focus trap/focus 복귀, 지도 pan 기준 고정, 역순 지역 응답, 정상 빈 목록, 실패/재시도, 누락·0 거리.
- 실제 운영의 일반 near GET 응답을 parser와 대조: 서울 기준12곳/서울도서관/0.03km, 부산 기준12곳/부산광역시 연제도서관/1.12km, 모두 HTTP200. 이 endpoint는 다른 목록과 달리 bare array를 반환하므로 관측된 배열 및 data envelope만 명시적으로 지원한다. 강제 갱신/운영 GPS/개인 데이터 변경 없음.
- jsdom 테스트는 실제 브라우저 시각적·GPS 권한 검증과 별개다. PR 전체 CI·프리뷰 화면 검증 후 운영 웹 배포 여부를 확인한다. 실제 카메라/GPS 권한·실제 좌표는 테스트 중 요청하지 않는다.
