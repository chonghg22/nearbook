# Promotion Experiment Plan

목표: 사용자가 거의 없는 상태에서 대규모 홍보가 아니라, 계측이 붙은 작은 홍보 실험으로 첫 반응을 확인한다.

기간: 2주  
예산: 0원  
핵심 지표: `library_status_view`가 발생한 세션 수  
실험 전제: `nearbook.events` 적재 확인 완료

## 공통 규칙

모든 링크에는 `source`를 붙인다.

```text
https://www.near-book.com/?source=community-bookclub
https://www.near-book.com/?source=community-parenting
https://www.near-book.com/?source=community-local
https://www.near-book.com/search?q=한강&source=post-hangang
```

금지할 표현:

- 예약까지 자동으로 된다
- 실시간 대출 가능 여부를 보장한다
- 전국 모든 도서관을 완전하게 보여준다

쓸 표현:

- 책 보유 여부와 대출 가능성을 확인한다
- 실제 상태는 도서관에서 최종 확인한다
- 데이터 오류나 개선 의견을 받고 있다

## 실험 A: 독서 커뮤니티

대상:

- 온라인 독서 모임/독서 커뮤니티
- 책 추천 글이 오가는 커뮤니티
- 독서 기록/서평을 공유하는 SNS

Source:

```text
community-bookclub
```

게시 제목 후보:

```text
책 사기 전에 동네 도서관에 있는지 확인하는 웹앱을 만들었습니다
```

게시글 초안:

```text
안녕하세요. 책을 사기 전에 가까운 공공도서관에 있는지 먼저 확인할 수 있는 작은 웹앱을 만들었습니다.

서비스 이름은 우리동네책입니다.
https://www.near-book.com/?source=community-bookclub

책 제목, 저자, ISBN으로 검색하면 근처 공공도서관의 보유 여부와 대출 가능성을 확인할 수 있습니다.

제가 이걸 만든 이유는 책을 읽고 싶을 때마다 서점, 도서관 사이트, 검색창을 따로 열어보는 과정이 번거로웠기 때문입니다. 공공도서관 데이터는 있지만 일반 사용자가 빠르게 확인하기에는 아직 불편한 부분이 많다고 느꼈습니다.

현재 가능한 것:
- 책 제목/저자/ISBN 검색
- 가까운 도서관 기준 보유 여부 확인
- 인기/급상승/카테고리 도서 탐색
- 위시리스트와 알림
- 바코드 스캔

아직 한계도 있습니다.
도서관 데이터는 외부 공공데이터와 각 도서관 제공 정보를 기반으로 해서 실제 현장 상태와 다를 수 있습니다. 예약이나 대출은 각 도서관 공식 사이트에서 최종 확인해야 합니다.

써보시고 검색이 잘 안 되는 책, 도서관 정보 오류, 헷갈리는 화면이 있으면 알려주시면 개선하겠습니다.
```

성공 기준:

- 방문 세션 100+
- 검색 실행률 30%+
- 책 상세 진입률 25%+
- 댓글/피드백에서 반복 문제 3개 이상 수집

## 실험 B: 학부모/책육아

대상:

- 책육아/초등 독서/학부모 커뮤니티
- 방학 독서 목록, 추천도서, 전집/단행본 선택 이야기가 오가는 곳

Source:

```text
community-parenting
```

게시 제목 후보:

```text
아이 책 사기 전에 도서관에 있는지 먼저 확인하는 방법
```

게시글 초안:

```text
아이 책을 매번 사기 전에 가까운 도서관에 있는지 먼저 확인하고 싶어서 만든 웹앱을 공유합니다.

우리동네책
https://www.near-book.com/?source=community-parenting

책 제목이나 저자명으로 검색하면 주변 공공도서관의 보유 여부와 대출 가능성을 확인할 수 있습니다.

이런 경우에 특히 유용합니다.
- 추천도서 목록을 받았는데 전부 사기 부담스러울 때
- 아이가 좋아할지 몰라 먼저 빌려보고 싶을 때
- 방학 독서 리스트를 도서관에서 해결하고 싶을 때
- 같은 책이 어느 도서관에 있는지 빠르게 보고 싶을 때

위치 권한을 허용하면 가까운 도서관 기준으로 볼 수 있고, 거부해도 검색과 지역별 도서관 탐색은 사용할 수 있습니다.

다만 도서관 데이터는 갱신 지연이 있을 수 있어서, 실제 예약/대출 전에는 해당 도서관에서 최종 확인하는 것이 좋습니다.

써보시고 아이 책 검색이 잘 안 되거나 도서관 정보가 다르면 피드백으로 알려주세요.
```

성공 기준:

- 방문 세션 100+
- 검색 실행률 40%+
- 도서관 확인 완료율 20%+
- 위시리스트 추가 또는 알림 설정 반응 확인

## 실험 C: 지역 커뮤니티

대상:

- 동네 생활 커뮤니티
- 지역 도서관 이용자가 모인 곳
- 아파트/맘카페/지역 게시판

Source:

```text
community-local
```

게시 제목 후보:

```text
우리 동네 도서관 책 찾기를 한 번에 확인하는 사이트
```

게시글 초안:

```text
동네 공공도서관에서 읽고 싶은 책을 찾을 때 여러 도서관 사이트를 따로 열어보는 게 번거로워서 만든 웹앱입니다.

우리동네책
https://www.near-book.com/?source=community-local

책 제목을 검색하면 가까운 도서관의 보유 여부와 대출 가능성을 확인할 수 있습니다. 위치 권한을 허용하면 현재 위치 주변 도서관을 우선 보여주고, 지역별 도서관 탐색도 가능합니다.

현재는 공공도서관 데이터 기반이라 실제 현장 상태와 차이가 있을 수 있습니다. 정확한 예약/대출은 도서관 공식 사이트에서 최종 확인해 주세요.

지역 도서관 정보가 다르거나 자주 쓰는 도서관이 잘 안 나오면 알려주세요. 오류 신고를 바탕으로 계속 고치고 있습니다.
```

성공 기준:

- 방문 세션 50+
- 위치 허용 또는 지역/도서관 탐색 행동 확인
- 도서관 클릭 세션 10+

## 실험 D: 개인 블로그/런칭 노트

Source:

```text
blog-launch-note
```

제목 후보:

```text
공공도서관 책 검색을 더 쉽게 만들고 있습니다
```

구성:

1. 문제: 책을 찾으려면 서점, 도서관, 검색 사이트를 오가야 한다.
2. 해결: 책 제목으로 가까운 공공도서관의 보유 여부와 대출 가능성을 확인한다.
3. 현재 가능한 기능: 검색, 주변 도서관, 위시리스트, 알림, 인기/급상승 도서.
4. 한계: 실시간 보장/예약 자동화는 아니다.
5. 요청: 데이터 오류와 사용성 피드백을 받고 있다.

링크:

```text
https://www.near-book.com/?source=blog-launch-note
```

Day 1:

- 독서 커뮤니티 1곳 게시
- Supabase에서 `community-bookclub` source 유입 확인

Day 3:

- 학부모/책육아 커뮤니티 1곳 게시
- 검색어와 zero-result query 확인

Day 5:

- 지역 커뮤니티 1곳 게시
- 도서관 클릭과 위치 관련 피드백 확인

Day 7:

- `docs/analytics-weekly.sql`의 1, 2, 3, 4번 쿼리 실행
- 반복 피드백을 FAQ 또는 제품 개선 후보로 분류

Day 14:

- 채널별 퍼널 비교
- 다음 2주 동안 확대할 채널 1개만 선택

## 판단 기준

확대:

- 검색 실행률 30%+
- 책 상세 진입률 25%+
- 도서관 확인 완료율 15%+
- 부정 반응보다 구체적 개선 제안이 많음

수정 후 재시도:

- 방문은 있는데 검색 실행률이 낮음
- 검색은 있는데 zero-result가 높음
- 책 상세는 보는데 도서관 확인/클릭이 낮음

중단:

- 스팸/홍보성 반응이 강함
- 데이터 정확도 불만이 대부분임
- source별 세션이 너무 적어 판단 불가
