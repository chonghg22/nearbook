# P1-05 도서관 공식 사이트·길찾기 CTA

## 변경 범위

- 기존 API의 보유 현황 응답에 이미 포함된 `homepage`, `lat`, `lng`를 웹 파서가 보존한다. 추가 API 호출, API/공용 타입/DB 변경은 없다.
- 사용자 프리뷰에서 보유 현황 카드 대신 조회 오류가 표시됨을 확인했다. `LibraryStatus`에 남아 있던 절대 API 호출을 공통 `publicApiJson`의 same-origin `/api` 경유로 변경했다. 프리뷰 Origin으로 API GET200이지만 CORS 허용 헤더 없음, 운영 Origin은 허용 헤더 있음으로 차이를 확인했다. 실제 화면 컴포넌트의 요청 경로/CTA 렌더링/실패 후 재시도까지 DOM 회귀 테스트를 추가했다.
- 홈페이지는 명시적인 HTTP(S) 절대 URL만 허용하며 사용자명·비밀번호가 있는 URL, 상대 경로, 실행 스킴 등은 표시하지 않는다. 링크 정보 누락/오류로 정상 대출 상태를 버리지 않는다.
- 원본이 가리키는 서울도서관 HTTP 루트는 로컬에서 시간 초과, 공식 HTTPS 루트는 GET200을 확인했다. 이 정확한 루트 URL만 HTTPS로 연결하고, 다른 도서관이나 임의 경로는 일괄 변경하지 않는다. DB 원본은 수정하지 않는다.
- 목적지 좌표와 도서관명을 [카카오맵 공식 길찾기 URL](https://apis.map.kakao.com/web/guide/#routeurl)에 연결한다. 좌표 누락/오류 시 길찾기를 숨긴다. 출발지, 사용자의 GPS, 저장 위치를 전송하거나 GPS 권한을 요청하지 않는다.
- 공식 확인·길찾기는 새 탭 및 `noopener noreferrer`로 열고 기존 `library_click` 이벤트를 유지한다.
- `reservationUrl`의 모호한 이름을 실제 의미인 `homepageUrl`로 변경한다. 검증된 책별 검색/예약 링크 레지스트리가 없으므로 임의 URL을 생성하지 않는다. 예약 접수가 아니며 공식 사이트에서 직접 확인해야 한다고 명시한다.
- 대출 상태·소장 여부·기준점 거리·확인 시각을 CTA보다 먼저 표시한다. 책 페이지의 기존 순서(도서관 → 분석 → 광고 → 구매/제휴)는 유지한다.
- API CD, 지도 SDK/허용 URL/권한, PWA 캐시 정책, 다음 P1-06은 변경하지 않는다.

## 검증 기준

- 실제 보유 API 응답이 파서 → 상태 저장 → 재파싱 → 카드까지 홈페이지·목적지 좌표를 유지하는지 확인한다.
- 누락/잘못된 홈페이지·좌표에서도 정상 보유 상태와 내부 상세 링크를 유지한다.
- 네 상태 및 오래된 조회 정보에서 공식 확인 CTA가 보이며 자동 예약을 암시하지 않는다.
- 키보드·모바일 터치 타깃·새 탭 안내·클릭 이벤트를 테스트한다.
- 전체 frozen install / lint / type-check / build / test / CI 및 프리뷰 화면을 검증한다. 외부 사이트 로그인·실제 예약은 수행하지 않는다.
