## 이번 변경과 현재 정책

위시리스트와 내 도서관의 `Pro 알아보기`는 연결 주소나 이벤트 처리기가 없는 버튼이었다. 실제로 이용할 수 있는 업그레이드 경로가 없으므로 무제한 이용 홍보와 버튼을 제거하고, 무료 계정의 현재 한도와 기존 책·도서관을 제거한 뒤 추가하는 방법을 안내한다. 도서관 교체 후에는 기본 도서관을 다시 선택하도록 안내한다. 구매·결제가 가능하다는 인상을 주는 대체 버튼은 만들지 않는다.

현재 소스 기준 무료 찜은 **10권**, 저장 도서관은 **1곳**이다. `WishlistsService.add`와 `LibraryCardsService.add`가 서버에서 제한하며 같은 항목 재등록은 멱등 처리한다. 기존 `pro` 데이터 모델과 해당 계정의 동작은 유지한다. 이는 판매 중인 요금제나 가격이 확인됐다는 뜻이 아니다. 가격·결제·기존 계정 플랜·저장 한도는 변경하지 않는다.

근거 파일: `apps/web/app/me/wishlist/_components/wishlist-view.tsx`, `apps/web/app/me/libraries/_components/library-cards-view.tsx`, `apps/api/src/modules/wishlists/wishlists.service.ts`, `apps/api/src/modules/library-cards/library-cards.service.ts`. 서버의 한도 검증 테스트는 `apps/api/src/modules/wishlists/personal-flows.spec.ts`에 있다.

## 재방문 실험안

아래는 검토 가능한 제안이며 이번 PR에서 기록 저장이나 계정 병합을 활성화하지 않는다. 동작하지 않는 CTA 정리와 실험 설계를 이번 티켓의 구현 범위로 삼는다.

| 후보 | 기대 효과 | 비용·주의점 | 검토 결과 |
| --- | --- | --- | --- |
| 최근 본 책 | 지난번 책 상세로 바로 재진입 | 공용 기기의 독서 이력, 삭제·만료 처리 필요 | 첫 실험 후보 |
| 최근 검색 | 검색어 재입력 감소 | 검색어에 개인 정보가 포함될 수 있음 | 최근 본 책 효과 확인 후 검토 |
| 비로그인 임시 찜 | 가입 전에 관심 책 보관 | 서버 찜과 차이·유실·병합 실패·한도 설명 필요 | 첫 실험에서는 제외 |
| 로그인 후 자동 병합 | 가입 전 행동 연결 | 공용 기기의 이전 사용자 이력이 다른 계정으로 들어갈 수 있음 | 자동 병합은 제안하지 않음 |

첫 후보는 **사용자가 켠 경우에만 이 브라우저에 최근 본 책을 저장**하는 기능이다. 첫 화면에서 “이 기기에 최근 본 책 저장”과 삭제 방법을 설명하고, 초기값은 끔으로 제안한다. 서버 조회 성공으로 정상 책 상세가 표시된 경우만 기록한다. 오류·404·prefetch는 방문으로 계산하지 않는다. 기존 찜과 별도 목록임을 표시한다.

제안 저장 범위는 ISBN·마지막 방문 시각만, 최대 10권·30일이다. 제목·표지는 표시할 때 공개 메타데이터로 조회하고, 저장한 대출 가능 여부를 현재 상태로 재사용하지 않는다. GPS·도서관 카드·계정 ID·인증 정보·알림 설정·자유 입력 메모는 저장하지 않는다. 이 수치와 저장 방식은 실험 시작 전에 확정할 항목이며 현재 서비스 정책이 아니다.

기록 전체 삭제·저장 끄기를 같은 위치에서 제공하고, 끄면 기존 기록도 지운다. 만료·잘못된 데이터·저장소 거부·용량 초과는 정상 검색을 막지 않아야 한다. 로그인·로그아웃·계정 전환 때 기록을 비우고 저장을 끈다. 기존 SW 캐시 정리는 localStorage를 지우지 않으므로 이 경계를 별도로 구현해야 한다. 다른 탭의 삭제·계정 전환도 반영한다. 서버 찜에 자동 등록하지 않는다.

임시 찜을 후속 검토할 경우에는 로그인 후 선택한 항목만 가져오도록 하고, 중복 ISBN 제거·서버가 판정한 잔여 한도·실패 항목 유지·최종 목록 재조회·재시도 멱등성을 먼저 검증한다. 가져오기는 명시적 사용자 행동으로만 실행한다.

## 실험을 시작할 조건과 판단 방법

1. 저장 켜기·보관 기간·공용 기기 안내·삭제·계정 경계 UI를 검토하고 범위를 확정한다.
2. P2-02에서 실제 조회 완료와 다음 행동 이벤트를 구분한다. 기존 분석은 브라우저 ID를 사용하므로 기록 삭제와 분석 ID 삭제가 같다고 안내하지 않는다. 이력 전체나 새 검색어를 실험 분석에 추가 전송하지 않는다.
3. 기능을 켠 집단과 끈 집단의 관측값을 따로 보고, 자기 선택 효과 때문에 차이를 인과 효과로 단정하지 않는다. 지표는 7일 내 재방문, 최근 본 책 재진입 후 보유 조회 완료·공식 링크 이동, 오류·삭제·끄기 비율이다. 활성 사용자 수와 표본·관측 기간도 함께 기록한다.
4. 최소 2주 관측 후 효과와 사용자 피드백을 검토한다. 표본이 작으면 결론을 보류하고, 개인정보 잔류·잘못된 계정 병합이 발견되면 확장을 중단한다. 광고·외부 게시·비용 집행은 이 실험안에 포함하지 않는다.

## 요금 기능을 다시 노출할 조건

유료 CTA는 실제 이용 경로, 제공 기능·한도, 가격·청구 주기, 해지·환불 안내와 결제 성공/실패 처리가 확정되고 검증된 뒤 검토한다. 이 문서는 가격이나 출시를 승인하지 않는다. 현재는 동작하지 않는 버튼을 제거하는 것으로 마무리한다. P1-11 이메일·푸시 개선 보류는 유지한다.
