# P1-08 보유·대출 상태에 따른 다음 행동

## 범위와 원칙

P1-07 운영 main `4fa9883` 기반 웹 전용 변경이다. 기존 holdings API는 이미 반경1~20km, 후보 최대30곳, 상태 조회 최대10곳을 지원한다. API·DB·공용 계약·지도 허용 URL·PWA·알림 발송/수신 정책은 변경하지 않는다. 검색 결과 카드별 소장 미리보기는 이번에 추가하지 않으므로 추가 fan-out도 없다. P1-09에는 착수하지 않는다.

## 화면과 동작

- 책 상세에 반경5/10/20km 버튼과 실제 조회 범위를 표시한다. 기본은5km이며 자동 확대·반복 조회는 없다.
- 대출 가능0곳 또는 endpoint 실패일 때 ‘책을 찾는 다른 방법’ 패널을 표시한다. 기존 미소장/대출 불가/미확인/일부 미조회/후보 없음/오류 문구와 공식 링크 카드를 유지한다. 미확인·실패를 미소장으로 바꾸지 않는다.
- 반경 확대는5→10→20km로 사용자가 선택한 경우에만 실행한다.20km 이후 무한 확대하지 않는다. 반경이 커져도 가까운 후보가 같으면 결과가 같을 수 있으므로 다른 기준 지역 선택을 함께 제공한다. 모든 도서관을 확인했다고 주장하지 않는다.
- 패널의 지역 선택은 기존 LocationBar/LocationModal을 재사용한다. GPS는 자동으로 요청하지 않는다. 기존 버튼 이름은 유지하고 패널 버튼만 ‘다른 지역·도서관 선택’으로 표시한다.
- 같은 제목·다른 판본 검색은 현재 제목의 콜론 앞 부분(없으면 원 제목)으로 `searchType=title` 검색에 이동한다. 최대200자·URL 인코딩을 적용한다. 이는 제목 검색 휴리스틱이며 같은 내용/동일 판본/소장 여부를 보장하거나 ISBN을 합치는 기능이 아니다. 검색 결과의 제목·ISBN·큰글자/필사 표기를 사용자가 비교한다.
- 찜은 상단 기존 `#book-wishlist`로 이동한다. 새 WishlistButton을 중복 마운트하거나 자동 저장하지 않는다. 알림은 기존 `/me/notifications` 설정으로 이동하고, 로그인 요구·사용자 직접 수신 설정·대출/예약 보장 불가를 안내한다. 알림을 자동 활성화하거나 발송하지 않는다.
- 공식 사이트는 기존 검증된 도서관 카드 링크를 유지한다. 카드가 없으면 `/libraries`에서 도서관 상세/공식 사이트를 찾게 한다. 소장 검색·예약 URL을 지어내지 않는다.
- 패널 내부 이동 링크는 prefetch를 꺼서 패널 노출만으로 검색/개인 설정/도서관 페이지를 미리 요청하지 않는다.

## 요청·개인정보

- 기존 same-origin `publicApiJson` 경로와15초 timeout/strict holdings parser를 유지하고 `radius`만 명시한다. auth token·Supabase session을 보유 조회에 추가하지 않는다.
- 요청 중 반경 버튼을 비활성화하고 같은 반경 재선택은 무시한다. 새 요청/위치/ISBN 변경 시 이전 요청을 abort하고 늦게 온 결과를 버린다. 실제 공급자 요청의 서버 취소까지 보장하지는 않는다.
- 책 또는 기준 위치가 바뀌면5km로 돌아가며 이전 지역으로 다시 가도 옛20km 선택을 되살리지 않는다. 반경을 저장하거나 GPS를 추가 요청하지 않는다.
- 30초 timer는 기존 관측의 stale 여부만 갱신하며 네트워크 재시도/자동 확대를 하지 않는다. 각 실제 조회의 공급자 호출은 기존 서버 상한과 캐시에 따른다. 모든 사용자에 대한 전역 한도/작업 병합은 이번 변경 범위가 아니다.
- 기존 조회 이벤트에 radiusKm만 추가한다. 좌표를 새로 이벤트에 추가하지 않는다.

## 검증과 배포 조건

실제 LocationProvider/LocationModal·LibraryStatus·public API client·strict parser·HoldingsView·LibraryCard를 포함한 jsdom 테스트로 상태별 다음 행동, 공식 링크 유지,5→10→20 확대와 상한/동일값 무요청/로딩 비활성화, 실패 재시도, 새로운 책/지역의5km 복귀 및 이전 요청 abort/늦은 응답 무시, 지역 선택/GPS 무요청, timer 무조회를 검증한다. 제목 링크의 안전 인코딩·길이·없는 제목 처리를 별도 검증한다. 기존 홈 위치/보유 상태/공식 링크 및 전체 CI를 유지한다.

사용자 ‘검증 후 운영 웹 반영’ 승인을 수신했다. 최종 CI와 프리뷰 검증 후에만 운영 웹에 반영한다. API 컨테이너 교체·DB·강제 데이터 갱신·지도 설정 변경은 없다. 실제 계정 찜/수신 설정/알림 발송/예약은 테스트하지 않는다.
