# P0-03 지도·지역 목록 복구 — Claude Code 구현 인계

작성일: 2026-10-13  
상태: **Claude Code 구현·보완 반영 / 전체 CI 및 목록·SDK 실패·모바일 프리뷰 검증 통과 / 정상 지도 실동작·운영 반영 대기**

## 역할

- Claude Code: 구현, 회귀 테스트 코드 작성, 검토 지적사항 수정.
- Codex: 요구사항·완료 기준 정리, 독립 코드 검토, 테스트 실행·브라우저 검증.
- 이번 항목의 구현은 완료 기준 검증 전까지 TODO에서 완료 처리하지 않는다.
- 이번 문서는 배포 승인이나 배포 완료 기록이 아니다.

## 확인한 운영 증상

`https://www.near-book.com/libraries`에서 다음 순서로 재현했다.

1. 목록 모드로 전환한다.
2. 시도를 `부산광역시`로 선택한다.
3. 시군구를 `해운대구`로 선택한다.
4. 선택값은 변경되지만 목록은 `가온도서관`, `강남구립논현도서관` 등 서울 목록으로 남는다.

DOM에서도 선택값 `[부산광역시, 해운대구]`와 첫 목록의 서울 주소를 함께 확인했다.

같은 지역의 `/api/libraries/region-center?sido=부산광역시&sigungu=해운대구`는 정상 응답했다.

```json
{"lat":35.19401008333333,"lng":129.14151728333334,"zoom":13}
```

이는 해당 지역 중심 API의 장애가 아니라, **지도 이벤트에 의존한 목록 갱신** 문제가 존재함을 보여준다. 모든 지역/API의 정상 동작을 증명한 것은 아니다.

변경 전 화면: [부산·해운대구 선택에도 서울 목록 유지](../../.tools/nearbook-evidence/p0-03-before-region-change.jpg)

## 소스 검토

- `apps/web/app/libraries/_components/libraries-map-view.tsx`
  - 목록 조회 인자는 지도 `bounds`뿐이다.
  - 시도/시군구 변경은 `regionCenter`만 바꾼다.
  - 목록 모드에서는 지도 컴포넌트가 언마운트되므로 새로운 bounds 이벤트가 발생하지 않는다.
  - 지역 중심 요청은 non-OK 검사, 제한 시간, 취소·오래된 응답 보호, 사용자 오류 안내가 없다.
- `apps/web/hooks/use-map-libraries.ts`
  - 기본 서울 bounds로 조회할 수 있으나 선택 지역과 연결되지 않는다.
  - 이전 요청의 `finally`가 새 요청의 로딩 상태를 해제할 수 있다.
  - debounce 시점보다 먼저 도착하는 이전 응답 및 언마운트 처리도 검토가 필요하다.
  - 목록 스키마 검증, 시간 제한, 재시도 동작이 없다.
- `apps/web/hooks/use-naver-map.ts`
  - SDK 실패 시 서울 bounds를 전달한다. 선택 지역을 덮어쓰지 않도록 호출자와 함께 정리해야 한다.
  - SDK 로딩 실패·대기 시간, 재마운트, 이벤트 리스너 정리도 검토한다.
- `apps/web/app/api/libraries/{in-bounds,region-center}/route.ts`
  - P0-01의 `SERVER_API_BASE_URL` 경로는 이미 반영됐으므로 유지한다.
  - 시간 제한, 입력·응답 검증, 일관되고 민감정보 없는 오류 응답이 필요하다.
- API `findByRegionWithSigungu`는 `{data: [{id,name,lat,lng}]}`를 반환하며 최대 200건이다. 주소는 현재 선택 필드에 없다. 목록에 주소를 추가한다면 실제 계약과 타입을 함께 맞추고 전체 건수처럼 오인시키지 않는다.

## Claude Code 구현 범위

1. 지역 선택과 목록 조회를 지도 SDK/표시 여부에서 독립시킨다.
   - 목록·지도·분할에서 같은 선택 지역을 기준으로 일관되게 조회한다.
   - 시도 변경 시 시군구를 초기화하고 새 지역을 즉시 조회한다.
   - 전체 시군구/전체 시도로 복귀하는 동작도 정의한다.
   - 지도 이동 조회와 지역 필터의 우선순위를 명확히 하고, 오래된 지도 이벤트가 새 선택 지역을 덮어쓰지 않게 한다.
2. 지도 SDK 실패/미로드 시 목록 대체 경로를 제공한다.
   - 지도 단독 모드에서도 사용자에게 오류와 목록 보기 버튼을 제공한다.
   - 지도 실패를 특정 지역에 도서관이 없는 상태로 표시하지 않는다.
3. 정상 로딩·실제 빈 결과·요청 실패를 구분하고 재시도를 제공한다.
   - 실패/빈 중심 좌표 응답이 이전 지역을 새 지역처럼 남겨두지 않도록 처리한다.
4. 요청의 timeout·취소·non-OK·스키마 검증을 보완한다.
   - 빠른 연속 선택, 지도 이동, 언마운트에서 최신 요청만 상태를 갱신한다.
   - 서버 프록시 오류에 원본 URL, 응답 본문, 토큰, 내부 오류 상세를 노출하지 않는다.
5. 기존 SEO 목록·canonical·서버 API 주소 정책은 보존한다.

대규모 지도 재작성, 개인정보 위치 권한 획득, 인프라/환경변수 변경, DB 마이그레이션은 범위에서 제외한다. 구현에 필요한 최소 API 응답 계약 변경은 근거를 설명한다.

## 검토·테스트 완료 기준

- 목록 모드에서 서울 → 부산 → 해운대구 변경 시 관련 도서관으로 갱신된다.
- 시도 변경 후 이전 시군구가 남지 않고 전체 선택 복귀가 정상 동작한다.
- 지도·분할에서 목록과 마커의 기준이 일관되고 지도 이동도 정의한 정책대로 동작한다.
- SDK 실패에서도 같은 지역 목록을 볼 수 있다.
- 빠르게 지역 A → B를 선택했을 때 늦은 A 응답/오류/finally가 B를 덮어쓰지 않는다.
- HTTP 429/5xx, 네트워크 오류, timeout, 잘못된 JSON/스키마가 정상 0건과 구분된다.
- 유효한 빈 배열은 정상 빈 결과로 표시하고 재시도 후 복구할 수 있다.
- 프록시 입력 검증·시간 제한·응답 검증·민감정보 미노출 회귀 테스트를 추가한다.
- 전체 lint/type-check/build/test 및 대표 브라우저 흐름을 통과한 뒤 완료 처리한다.
- 390px에서 지역 선택/목록 전환 버튼이 잘리지 않는지도 확인한다.

현재 의존성이 없는 환경에서는 dependency-free Node 테스트를 우선 사용하되, 소스 문자열 검사만으로 실제 React 동작 검증을 대체하지 않는다. 실행하지 않은 테스트나 브라우저 시나리오는 명확히 미검증으로 기록한다.

## 작업 보존·실행 제약

기존 기준선 테스트를 다시 실행했다.

```sh
node --test apps/web/scripts/api-config.test.mjs apps/web/scripts/detail-request.test.mjs
```

결과: **54개 통과, 실패 0**. 이는 기존 P0-01/02 회귀 검증이며 아직 구현하지 않은 P0-03의 통과 결과가 아니다. 문서 변경 후 `git diff --check`도 통과했다.

- 저장소에는 이전 P0-01/02와 배포 기록의 dirty/untracked 파일이 있다. 기존 변경을 모두 보존한다.
- 로컬 HEAD는 `76d6265`, 마지막 확인한 remote main은 `600a7bb`다. 로컬 diff 전체를 이번 변경으로 취급하지 않는다.
- reset/checkout/clean, 임의 commit/push/merge/deploy, 실제 env/토큰 읽기·출력, 인증 재설정은 하지 않는다.
- 파일 편집에는 `apply_patch`를 사용한다.
- 초기 실행에서는 결과 없이 중단했고 일반 `curl` DNS 진단도 실패했다. 그러나 이후 CLI 모델 요청은 실제 `READY` 응답으로 성공했다. 일반 DNS 실패만으로 Claude 실행 불가라고 판단한 초기 결론은 정정한다.
- Claude Code에서 Bash 기반 `apply_patch` 호출은 자체 권한 검사로 거부됐다. 해당 호출은 중단했다. Claude에는 읽기 전용 도구만 제공해 구현 패치를 작성하게 하고, Codex가 검토 후 별도로 허용된 전용 `apply_patch`로 적용한다. 제한된 권한을 우회하거나 사용자에게 실행을 넘기지 않는다.
- 구현 작성·수정은 Claude Code, 패치 적용·독립 검토·테스트·상태 기록은 Codex가 담당한다. 검증 결과는 아래에 후속 기록한다.

## 1차 구현·독립 검증

- Claude Code가 작성한 14개 파일 패치를 Codex가 검토해 적용했다. 지역 필터가 지도 bounds보다 우선하도록 목록 조회를 분리하고, 엄격한 응답 검증·시간 제한·요청 취소·최신 요청 가드·재시도·지도 SDK 실패 목록 대체 경로를 추가했다.
- `/api/libraries/by-region`은 기존 upstream의 목록에 중심 좌표와 200건 제한 표시를 함께 제공한다. 기존 API는 주소가 없어도 호환되며, 최소 backend 보완으로 주소 선택 및 이름 정렬을 추가했다.
- Node 테스트: 기존 54개 + 새 지도 관련 45개 = **99개 통과, 실패 0**.
- Codex 별도 late-response A→B 테스트: 서울 응답이 뒤늦게 완료돼도 부산 요청의 최신 상태 유지 확인.
- `map-libraries.mjs`의 TypeScript `--allowJs --checkJs --noEmit --strict` 검사 통과(전역 Vercel 설치에 포함된 TypeScript 사용). 이는 전체 앱 타입 검사 통과를 뜻하지 않는다.
- `git diff --check` 통과.
- 운영 기존 by-region 계약: 강원특별자치도 51개, 숫자형 좌표, 주소 필드 없음 확인.
- 검토 보완 요청: 지도 단독 모드의 목록 요청 오류/빈 결과/로딩 UI, 시군구 중심 미확정 시 이전 지역 중심 표시, SDK 늦은 복구의 오류 초기화·리스너 정리, 이전 InfoWindow 닫기, 모바일 최초 렌더 hydration 불일치.
- 390px viewport 설정을 요청했지만 실제 DOM 폭이 1914px로 남았다. 설정을 복원했고 모바일 브라우저 검증은 미완료로 남긴다.
- 현재 전체 CI/프리뷰/운영 배포 및 변경 후 브라우저 검증은 미완료다.

### 검토 보완 반영

- Claude가 보완 패치를 작성하고 Codex가 검토·적용했다. 지도 단독 모드에도 데이터 로딩/오류/빈 결과와 재시도·목록 전환을 표시한다.
- 시군구 중심이 아직 없으면 현재 시도 중심으로 이동한다. SDK 늦은 초기화 성공 시 오류를 해제하고, 실패 시 이전 지도/idle 리스너를 정리하며 글로벌 인증 콜백 소유권을 확인한다.
- 마커 목록 변경/언마운트 시 이전 InfoWindow를 닫고, SSR/최초 클라이언트 렌더 모드를 일치시켰다.
- Node 테스트 **100개 통과**(기존 54 + 지도 관련 46), 공통 JS strict 검사 및 diff-check 재통과.
- [PR #6](https://github.com/chonghg22/nearbook/pull/6)으로 전체 CI와 Vercel 프리뷰를 검증한다. 최종 보완 커밋 검증 전에는 병합하지 않는다.

### 프리뷰 실동작 검증과 추가 보완

- `e4b9ea4`의 전체 CI 통과: Node 100 + Web Vitest 106 + API Jest 11 = **217개**, 의존성 설치·lint·전체 타입 검사·빌드 통과. [CI 실행](https://github.com/chonghg22/nearbook/actions/runs/38326092905)
- 프리뷰 목록 모드에서 부산 → 해운대구 **6개** 조회, 빠른 서울 → 부산 → 해운대구 변경 및 전체 시군구 복귀를 확인했다. 이전 서울 목록은 새 지역 로딩 중 제거된다.
- 지도 모드에서 프리뷰 도메인의 SDK 인증 실패를 이용해 대체 UI를 검증하던 중, Naver SDK가 내부 객체를 null로 바꾸어 정리 함수가 예외를 던지고 목록 전환 안내를 막는 실제 결함을 발견했다. CI 통과만으로 완료 처리하지 않았다.
- Claude의 추가 수정: 참조를 먼저 비우고 SDK 정리를 단계별 best-effort로 수행하며, 오류 상태를 정리보다 먼저 설정한다. 목록 전환 안내는 패널 상단으로 이동해 첫 화면에서 보이게 한다.
- 추가 수정 로컬 검증: Node **103개 통과**, 공통 JS strict 검사 및 diff-check 통과. SDK null/정리 예외 회귀 테스트를 포함한다. 모사 테스트·소스 검사는 실제 React/브라우저 검증의 대체가 아니다.
- 추가 수정의 전체 CI·프리뷰 재검증은 진행 중이다. 운영은 변경하지 않았다.

- 이전 viewport 미적용과 달리 최종 검증에서는 390×844 override가 실제 적용됐다(스크롤바 제외 DOM 폭 **384px**). 지역 필터·목록/지도 토글·오류 대체 버튼이 화면 안에 있고 수평 overflow가 없다. 모바일 `목록 보기` 후 같은 해운대구 6개 목록 확인, viewport는 검사 후 복원했다.

- 정상 빈 결과 실동작: 강원·삼척시 선택에서 목록 0개와 `선택한 지역에 등록된 도서관이 없습니다`를 표시했고, 부산·해운대구 재선택으로 목록을 다시 조회했다. 이는 현재 데이터셋의 빈 결과이며 삼척시 자체에 도서관이 없다는 뜻은 아니다.

- **F1:** 화면 상단의 성북길빛도서관(`111492`) 마커 클릭 시 InfoWindow의 자동 pan → idle → bounds 재조회로 목록 배열이 변경된다. 기존 effect cleanup이 팝업을 닫아 약 2.5초 후 상세 링크가 사라졌다. [증거](../../.tools/nearbook-evidence/p0-03-preview-edge-popup-disappears.jpg)

### F1/F2 추가 수정 적용·로컬 검증

- Claude 작성 패치를 검토·적용했다. 마커를 도서관 id로 유지하고 선택 변경에서는 아이콘만 갱신한다. 같은 조회 범위의 재조회는 열린 팝업을 유지하며, 지역 변경·해당 도서관 제거·지도 종료 시 닫는다. HTML escape 및 상세 링크 인코딩을 유지한다.
- 지도 크기는 SDK가 관리하는 요소가 아닌 React 래퍼의 ResizeObserver로 관찰한다. 양수·변경된 크기만 `setSize`에 반영하고 중심 유지 후 bounds를 알린다. 부모 패널 `min-w-0`로 분할 전환 시 축소를 허용한다. SDK 인증 실패/언마운트 시 observer를 먼저 끊고, `setSize` 중 정리되면 `setCenter`도 호출하지 않는다.
- 로컬 Node **120개 통과**(기존 103 + 새 회귀 17), 공통 JS strict 및 diff-check 통과. 새 테스트는 팝업/마커 identity·범위 변경·SDK null/예외·리사이즈/observer lifecycle을 모사하며 실제 브라우저 검증을 대체하지 않는다.
- 전체 CI와 인증된 수정 프리뷰 재검증은 아직 진행 전이며 운영은 미변경이다.
