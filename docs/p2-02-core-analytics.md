홈·헤더의 누락된 검색 제출을 검색 화면과 같은 계약으로 연결하고, 명시적 제출/자동완성 선택/결과 노출/실제 요청 결과를 분리했다. 결과 선택에는 페이지 기준 순위·유형·정렬을 기록한다. 보유 요청 결과/실패와 상태 화면을 구분하고 각 도서관 수·시간·오래된 정보·공식 사이트 클릭의 requestId를 전달한다.

기존 이벤트 저장 API/스키마를 유지하고 schemaVersion=2로 새 관측을 구분한다. 공개 방문 세션의 분모와 기간이 성숙한 7일 재방문 코호트를 추가했다. 상세 이벤트 계약·시간/관측 한계·운영 절차는 [runbook](analytics-runbook.md), 집계는 [weekly SQL](analytics-weekly.sql) 참고.

외부 API 예산·캐시 갱신·계정/요금/저장 한도·알림/발송·최근 본 책 저장 기능은 변경하지 않는다. 운영 사용자 이벤트나 개인 데이터를 조회해 효과가 입증됐다고 주장하지 않는다.

검증은 별도 기록한다. 병합·운영 배포 전에는 새 이벤트가 운영에서 수집된다고 표시하지 않는다.

로컬 검증: frozen lockfile 설치, 웹383개(기존365+추가18)·웹 lint/type-check·diff check 통과. 격리 PostgreSQL17의 임시 events 테이블에서 집계 SQL6개 및 순서/ISBN/재시도/7일 코호트 fixture 통과. CI에 같은 SQL 회귀용 PostgreSQL service를 추가했다. 기존 API용 실제 PG15개와 이 SQL 검증을 구분한다. 실제 운영 계정·이벤트 저장·수집 지표는 실행/조회하지 않았다.
